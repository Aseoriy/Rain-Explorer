- Strict Windows path, collision, link, count, metadata, hierarchy/synthetic-node, default 64 GiB decoded-output, declared/runtime ratio, exact decoded-size, filesystem-object accounting, and free-space policy.

## Restored package graph and native-provider gate

The centrally pinned managed/test packages have been restored with lock files and the solution-level NuGet vulnerability query is clean against the feed checked on 2026-08-22. SharpSevenZip remains only a centrally pinned candidate version and is intentionally not a project reference. Before the native provider can be referenced or enabled:

1. Inspect the SharpSevenZip package file list and exact source commit.
2. Verify its LGPL-3.0-or-later text, source availability, and absence of unexpected runtime payloads.
3. Acquire official 7-Zip 26.02 x64 from the official distribution, record SHA-256, and retain corresponding source.
4. Load only an absolute app-private `native\win-x64\7z.dll`; prove current-directory and `PATH` DLLs are ignored.
5. Repeat the managed conformance corpus against the native adapter, including encrypted ZIP, encrypted/header-encrypted 7z, RAR read, solid extraction, multipart reads, progress, cancellation, Unicode, corrupt input, and forced native failure.
6. Keep the gate disabled if any check fails. Managed 7z reading may remain available, but advanced creation stays unavailable.

Audit checkpoint on 2026-08-22: steps 1-3 passed for SharpSevenZip 2.0.109 and official 7-Zip 26.02, including signed-package verification, exact source commit, complete package assets, license texts, binary/source hashes, and byte identity between the package x64 DLL and the official installer DLL. Focused step-4 probes passed on .NET 10: the wrapper loaded the exact absolute selected DLL even with current-directory and first-`PATH` candidates present, while a missing selected path loaded no native module and failed closed. Core step-5 probes passed across the checked ZIP/7z/RAR corpus for ordinary, AES/ZipCrypto, solid, encrypted/header-encrypted, Unicode, selected streaming, and split-volume cases; bounded-stream cancellation, encrypted-header creation, split creation, rename, and deletion also worked. However, wrapper `Check()` accepted the checked truncated ZIP even though official 7-Zip reported `Unexpected end of archive` and exit code 2. Exact source drops native archive warning/error flags and omits per-entry packed size. Unmodified 2.0.109 is therefore rejected as an authoritative reader, and the gate remains disabled pending a newer upstream release or separately approved minimal fork plus typed password/cancellation behavior, packaged integration, and forced-process-failure checks. Wrapper update methods are additionally forbidden on user-owned archives because exact source inspection shows an unconditional delete-before-final-move path; future modification must operate only on a Rain-owned staging copy.
